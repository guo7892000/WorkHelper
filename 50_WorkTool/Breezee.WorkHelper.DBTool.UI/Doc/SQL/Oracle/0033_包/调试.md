### 包的调试
当执行包的存储过程很慢导致不能调试时，可以使用抛错的方式得到当时运行值。例如：
```
RAISE_APPLICATION_ERROR(-20001, '这是一个自定义错误消息'||var_debugInf); 
```

### 关于多表保存中因为最后一个表出错导致整个事务不成功，无法知道原因
问题现象：程序中调用包的存储过程，能很快返回信息。在PLSQL中输入相关参数，并调用，会卡住很慢，无法调试。
因为整个存储过程是一次性提交事务的，无法查看出错步骤前的数据情况。  
解决方法：在可能出现问题地方，加上commit。然后在PLSQL中打开SQL窗口，通过指定参数值调用（非调试模式），
然后直接看输出及之前保存表的数据情况，来判断问题原因。
```
declare
 -- Local variables here
 i integer;
 i_sessionid varchar2(100):='1o88BlI3AZXq2yzC4uqasngl.undefined';
 i_modletag varchar2(100):='qdVechileCodeDefDialog';
 i_type varchar2(100):='A';
 i_operaterid varchar2(100):='admin';
 o_chexk_result Sys_Refcursor;
 o_return_code varchar2(100);
 o_error_message varchar2(4000);
 o_sqlerrm varchar2(4000);
begin
 -- Call the procedure
 PKG_JF_QDPRDCODEDEF.P_IMPORT_CHECK(i_sessionid => i_sessionid,
                                    i_modletag => i_modletag,
                                    i_type => i_type,
                                    i_operaterid => i_operaterid,
                                    o_chexk_result => o_chexk_result,
                                    o_return_code => o_return_code,
                                    o_error_message => o_error_message,
                                    o_sqlerrm => o_sqlerrm);
                                   
   dbms_output.put_line(o_error_message);
   dbms_output.put_line(o_sqlerrm);                            
end;
```
